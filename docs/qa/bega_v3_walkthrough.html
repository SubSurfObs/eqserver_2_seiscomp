Workflow v3 · one station, end to end

BEGA through v3

DU.BEGA is a real, unconverted DU station. This is the exact sequence v3 runs for it, using its measured numbers from the Stage-1 index. You touch it at the two amber moments; everything else is machine, and every machine decision leaves a record.

1,389,000 source files 987 days with data active 2022 → 2026 1 stray 1999 day 3,015 single-channel stubs from 2026-03
1 · IdentityHUMAN · ~5 min

You approve one small contract for BEGA

Network DU (pass-through), location and channel codes resolved from the DU authority chain (the operator CSV at a pinned revision, then the live inventory, then FDSN, then the long-term archive). One epoch: EchoPro, velocity channels, c01/c02/c03 → N/E/Z, band letter from the measured sample rate. Accelerometer and triggered data: excluded — your default, stated per stream so it is a decision, not a filter.

artifact → identity/DU/DU.BEGA.yaml (hashed; this hash follows every byte to the ledger)
2 · IndexMACHINE · done

The scan already indexed every file

1,389,000 filenames parsed into the station database: dates, minutes, sessions, source types, grammar variants. This already exists for BEGA — it is where the numbers on this page come from.

artifact → DU.BEGA.db (content-identified, so stale indexes are refused downstream)
3 · SelectionMACHINE · ~min

The chooser writes 987 day-plans

For each day and channel it picks one source population, scored by measured coverage — never alternating between overlapping copies — and gap-fills only into true holes. Every rejected file is logged with the reason.

2023-01-24minutesdecision
telemetry population1,438wins the day (coverage)

A real BEGA day. Note it reverses the old "prefer disk" rule — here telemetry is the near-complete record, and the chooser follows the evidence instead of the habit that caused the WLSH losses.

Escalation 1 of 2: one day of data dated 1999, outside the approved epoch. The machine stops for that day only and asks: real early deployment, or corrupt timestamp? Your answer updates the contract; nothing else waits.
Escalation 2 of 2: 3,015 single-channel stub files from 2026-03 — vertical-channel telemetry fragments, the full data likely arriving by another route. Keep as Z-only, or exclude? One decision covers all 3,015 files.
artifact → DU.BEGA.2023.selection.sqlite … (bound to identity hash + index identity; converter refuses anything else)
4 · Convert + auditMACHINE · hours

Conversion executes the plans; the auditor checks the result

~987 station-days become SDS day files in a run-scoped workspace. Then the independent auditor reads samples back against the originals — the same tool that measured the VW archive at 99% — and checks the emitted names against your contract. It writes a receipt; no receipt, no promotion.

artifacts → output inventory (every file, sized and checksummed) + QA receipt
5 · PromoteMACHINE · dev1

The books must balance before BEGA is called done

Promotion copies exactly the inventory — never "whatever is in the staging folder" — onto the permanent archive, through the existing atomic, never-delete path. BEGA closes only when the equation holds:

expected 987 = converted 985 + no-data 0 + escalated 2 (1999 day · stub cohort)  ·  verified 985/985

Illustrative split — the two escalated items resolve into converted, no-data, or a waiver you authored. Until the columns balance, BEGA stays open and says why.

Total human time for BEGA: the five-minute contract plus two real questions. Under the old flow the same station would have produced a generated plan to approve (which review has shown was ceremonial) while the actual file choices happened silently in code. Multiply the machine lane by 61 indexed DU stations — the human lane grows only where stations raise genuine questions.
