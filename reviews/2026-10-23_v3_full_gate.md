### F4 — blocker — Four probes do not establish a population-month’s channel set and failures invent Z/N/E

- Where: `scan/coverage_planner.py:144-192,211-225,291-348`
- Status: verified
- Scenario: despite the `(population, month)` cache key, the cache is populated from only the first day of that month on which the population is encountered. The slice `files[::len(files)//4][:4]` can also inspect only the first four of a 5–7-file cohort and never deliberately includes the final file. A channel present only later that day or later in the month is omitted for the entire month. Conversely, if all probes fail or contain no recognized channel, the chooser silently assumes Z/N/E; probe errors and the `assumed_broadband` basis are not persisted in the `probes` table, which records only one of up to four paths. Phase3 accepts `--no-probe` selections and assumed-channel selections without review. Thus Class 2 can remain silently unfixed or nonexistent channels can be selected.
- Smallest fix or check: derive channel knowledge from all filename-exact rows plus deterministic probes spread across the whole population-month, including first/last and configuration transitions; persist every probe, error, and basis. Treat failed/ambiguous probes as a blocked selection, especially for DU, rather than assuming broadband Z/N/E. Add adversarial tests where a channel appears only in the fifth file, last day of a month, and after a mid-month recorder change.

### F5 — blocker — “Short fill” overlays data and mixed-format writes can replace the chosen winner

- Where: `scan/coverage_planner.py:195-288`; `scan/phase3_driver.py:917-960`; `../disk_to_sds/scripts/suds_convert.py:178-262`
- Status: verified
- Scenario: coverage is filename-minute coverage, not decoded time coverage. The 0.88× median rule marks a small winner file and adds one competing file for the same whole minute without measuring which seconds are absent. A direct call to `choose_day()` confirmed that a 50-byte winner at minute 0001 and a 100-byte alternative at minute 0001 are both selected. The two copies therefore overlay rather than fill a proven gap—the condition the B2 guard was intended to forbid. File order, not the selection’s winner rule, decides which samples survive `fast_merge_split(overlap='trim')`. On mixed SUDS/miniSEED days, SUDS is written first and miniSEED second; `write_sds()` places the new stream before the existing file, so equal-time miniSEED samples take precedence even when SUDS was the chooser’s winner. The output is also written multiple times, not combined and written once as the gate question requires.
- Smallest fix or check: replace the size heuristic with measured sub-minute intervals and add only the non-overlapping missing interval, or carry explicit time windows into conversion. Preserve winner priority independent of pathname and format. Decode all selected format/channel groups, apply restrictions, combine once in memory, merge once, trim once, and atomically write once. Prove STBK B2 and a mixed-format overlapping-minute case with deliberately different sample values.

### F6 — blocker — Negative timestamp drift is still corrected by dropping samples, and unsupported records silently bypass the reader guard

- Where: `scan/phase3_driver.py:225-402`; `../sudspy/sudspy/utils.py:205-280`; `../sudspy/tests/test_timestamp_fidelity.py:19-50`
- Status: verified
- Scenario: both new tests cover positive drift only. In `fast_merge_split`, drift more than half a sample late starts a new trace, but drift more than half a sample early enters the overlap branch: it rounds the offset, drops leading samples from the later trace, and appends the remainder on the prior emitted grid. That changes the recorded timing and can discard a real first sample, contrary to the as-timestamped ruling. The phase3 pre-scan initially splits both signs, but the resulting traces are immediately passed through this merge and negative-drift segments are trimmed together again. Separately, `_mseed_record_scan()` assumes one record length/byte order for the concatenated buffer and ignores fixed-header time corrections and Blockette 1001 microseconds; any shape it cannot parse returns `None`, after which phase3 silently uses a whole-buffer ObsPy read—the original welding path—with no QC flag.
- Smallest fix or check: treat accumulated drift beyond half a sample in either direction as a segment boundary; reserve overlap trimming for explicitly identified duplicate-source overlap, not clock drift. Make an unscannable buffer fail or QC-flag into a timestamp-preserving per-file/per-record read instead of whole-buffer fallback. Add negative-drift, 250/1000-Hz, mixed record-length, time-correction, and Blockette-1001 tests at both reader and merge layers.
