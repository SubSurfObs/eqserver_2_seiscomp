# Review: DU release v2.6 and rebuild queue s6  (2026-11-10, reviewer: Codex)

## Verdict

PROCEED.

Queue `eqserver_sweep_du_v2_rebuild_s6` may be promoted. The apparent 6,895
bad LKHRT samples are an auditor read artefact, not bad conversion output. The
remaining findings below do not justify holding waveform data or starting a
new conversion campaign.

## Findings

### F1 — should-fix — the auditor welds raw miniSEED records before comparing them

- Where: `scan/qa_verify.py:386-430`;
  `~/v3_test/es2/LKHRT.2023/audit_2023-10-27.json`; source
  `20231027_0506_LKHRT.ms.zip`, concatenated-member byte offset 8192.
- Status: verified.
- Scenario: the raw miniSEED fixed header at offset 8192 independently decodes
  to year 2023, day 300, 05:06:21.121, 412 HHZ samples. Decoding that record
  alone gives first values `4, 3, -4, -4, 0`; the v2.6 SDS output starts at
  exactly `.121` with exactly those values. The auditor instead gives the
  complete zip member to ObsPy in one call. ObsPy joins this record to its
  predecessor and presents it at `.125`, creating the reported 3,475 HHZ and
  3,420 HHN mismatches and false topology findings. My 2026-11-10 v2.5 F1
  conclusion was therefore wrong: it relied on the already-welded whole-file
  source view.
- Smallest fix or check: have the auditor decode miniSEED records separately
  and preserve every record's stated start before applying source precedence.
  Re-run only the LKHRT audit to clear the false finding. This is an auditor
  repair; do not reconvert or hold LKHRT.

### F2 — should-fix — relative sidecar naming does not itself preserve the sidecar

- Where: `scan/phase3_driver.py:1281-1297`;
  `../sds_staging_ledger/apply.py:393-400`.
- Status: verified.
- Scenario: each s6 manifest now contains a useful relative `file` name and
  all seven sidecar content hashes checked correctly. However, Stage 5 still
  copies only the JSON run manifest into the ledger; it does not copy the
  compressed precedence sidecar. The relative name will become durable only
  when that copy step is added.
- Smallest fix or check: copy the sidecar beside the permanent run record when
  convenient, or archive the queue sidecars before queue cleanup. This is
  bookkeeping, not a reason to delay waveform promotion or reconvert data.

### F3 — should-fix — LILH wrote two foreign-station traces outside its station directory

- Where: `scan/phase3_driver.py:1116-1173`;
  LILH 2019 s6 run manifest and staging files
  `2019/DU/AUKSC/HHZ.D/DU.AUKSC..HHZ.D.2019.096` and
  `2019/DU/BRIG/DHZ.D/DU.BRIG.6.DHZ.D.2019.026`.
- Status: verified.
- Scenario: two LILH source zips contain a short foreign trace alongside the
  LILH trace: one raw `S.AUKSC..HHZ` trace (120 samples) and one raw
  `AB.BRIG.6.DHZ` trace (1,211 samples). The adapter changes their network to
  DU but preserves the foreign station, so it writes two 512-byte files
  outside the `DU/LILH` unit. The other six s6 units have exact
  manifest-to-staging inventories. Stage 5 is scoped to `DU.LILH`, so these
  two files will not be promoted with LILH and the intended LILH output is not
  missing; this does not block s6.
- Smallest fix or check: quarantine the two stray staging files and, for future
  conversions, drop and record a miniSEED trace whose raw station differs from
  the unit station rather than writing it elsewhere or relabelling it. Do not
  reconvert LILH solely for these foreign traces.

### F4 — nit — add a focused regression for accepted-by-ruling promotion records

- Where: workflow-v3 commit `b04926a`,
  `scan/run_production_promote.py:218-230` in that commit.
- Status: verified.
- Scenario: the fix is correct: a missing `staging_root` falls back to the
  promoter's explicit staging root, while a missing `items_succeeded` no
  longer means an empty conversion. The inventory guard then examines the
  manifest and staged station-year normally. The three accepted s6 records
  exercise exactly that shape, but no regression was added with the change.
- Smallest fix or check: add a small unit test for a done record missing both
  fields when routine test maintenance next touches the promoter. This is not
  a promotion blocker.

## Checked and found OK

- **F1 conversion fix:** `_coalesce_pieces` now combines only an exact grid
  continuation. At a sub-half-sample seam it removes the minimum leading
  sample needed to prevent a standard reader welding the grids, preserves all
  remaining timestamps, and records `weld_guard_dropped`. The write/read
  regression covers the `.121`/`.125` shape and checks both retained values
  and the one counted omission.
- **Bounded effect of old joining:** old DU output could theoretically move a
  seam by at most half a sample, and the closing comparison would normally
  nearest-sample-align it rather than report it. The s6 rebuilds provide a
  practical upper-scale check: the new guard removed 91,487 boundary samples
  across all seven station-years, about 15.2 channel-minutes in total. The
  largest unit was LKHRT 2023 with about 703 channel-seconds over 314 converted
  days—less than 0.003% even against only one continuous 100 Hz channel, and
  much less across its actual channels. This is far inside the greater-than-99%
  recovery target. Do not census or rebuild already promoted DU data solely
  for this sub-half-sample issue.
- **F2 conversion fix:** BLAT 2023-10-30 now audits with zero missing time and
  zero bad samples. The one-slot leading authorization is safe because files
  contribute only samples they contain and the resolver prevents a lower
  priority copy from overwriting occupied time.
- **F4 release guard:** committed conversion now refuses an unknown identity
  for eqserver, `disk_to_sds` or `sudspy`. All seven s6 manifests and strict
  preflight records contain the intended clean pins.
- **s6 queue:** seven completion records exist. All seven manifests have
  readable selections, valid release identities and matching precedence
  sidecar hashes. Apart from F3's two foreign traces, the staging inventories
  exactly match their manifests.
- **Damaged-source rulings:** TPSOP 2017's proof compared 64,129,600 samples
  with zero bad values and found only 5.82 channel-seconds absent around the
  damaged records. The accepted LKHRT 2022/2023 and TPSOP 2017 records name
  every damaged source file, and their manifests show no other non-ok cause.
  This is within Dan's existing corrupt-source ruling.
- Queue `_rebuild_s5` has no completion record and remains abandoned. Nothing
  in this review authorizes its promotion.
- No blocker findings remain.
